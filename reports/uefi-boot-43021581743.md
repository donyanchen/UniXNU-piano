## 2. 第一次失败：Volume Corrupt（FAT32 读大文件）

```
UNIXNU: menu: timeout, booting default 0
UNIXNU: boot: entry 'xnu' (Xiaomi Pad 8 Pro: XNU first boot)
UNIXNU: xnu: handing off 0 staged kext(s) to loader
FSOpen: Open '\EFI\UniXNU\Payloads\kernel.macho' Success
```

（FAT32 簇数低于 EnhancedFatDxe 的门限会 `EFI_VOLUME_CORRUPTED`），他们把 payload
改成 FAT16。

## 3. 第二次失败：Unsupported（异常级不匹配）

```
UNIXNU: xnu: handing off 0 staged kext(s) to loader
FSOpen: Open '\EFI\UniXNU\Payloads\kernel.macho' Success
FSOpen: Open '\EFI\UniXNU\Payloads\kernel.macho.adt' Success
UNIXNU: menu: entry 0 returned Unsupported
```

`DarwinBoot.Boot()` 的守卫：

```c
if ((Request->KextCount != 0) || (Request->DeviceTree != NULL) ||
    (Request->DeviceTreeSize != 0) || (DarwinCurrentEl () != 4)) {
  Print (L"DARWINBOOT: unsupported inputs or exception level; firmware retained\n");
  return EFI_UNSUPPORTED;
}
```

日志里 `0 staged kext(s)`，且 `unixnu.toml` 的条目没有 `dtb` 键
（`UniXNUPrepareDeviceTree` 在 `Entry->Dtb == NULL` 时直接返回，Fdt 保持 NULL），
所以前三个条件都不成立 —— 触发的是**异常级不是 EL1**。

Mu-Silicium 的 SEC 在 EL2 时只配置 `HCR_EL2`（`SetupExceptionLevel2`）并留在 EL2；
DarwinBoot 的 `DarwinEnter` 又是 `br x1` 直接跳内核，不做 EL 切换，于是 XNU 会以
EL2 起来 —— 而 XNU 必须在 EL1。

## 4. 下一版的两处修改

| 补丁 | 内容 |
| --- | --- |
| `patches/darwinboot-el1.patch` | `Boot()` 接受 EL2；`DarwinEnter` 在 EL2 时 `HCR_EL2.RW=1`、`SPSR_EL2=EL1h|DAIF`、`ELR_EL2=入口`，`eret` 到 EL1 再进内核 |
| `patches/unixnu-payload-fat16.patch` | payload 卷改为 4 KiB 簇 FAT16（`mformat` 去掉 `-F`，加 `-c 8`） |

两处都在 `git apply --check` 下验证过能干净打上（DarwinBoot 补丁打在 pinned
`3c75734014cd`，payload 补丁打在 pinned UniXNU `95ad7812`）。
